# Реальный спотовый тест

Тестовый контест использует SOLUSDT Binance spot / Bybit spot и тот же API,
что synthetic demo: ZIP с `strategy.py` запускается в общем Docker-образе.
Конкурс 18505 остаётся закрытым инженерным тестом до приёмки организатором.

## Публичный Train

В разделе Files новой фазы доступен архив `train-SOLUSDT-spot-20261109.zip`:
четыре полных Parquet за 29 сентября — 2 октября 2026 UTC, `sources.json`,
`config.json` и каталог `quickstart/` с первым часовым эпизодом.
Quickstart содержит подготовленный `events.jsonl`, поэтому его можно сразу
оценивать. Полный многодневный Train ещё не проходил полный replay;
локальные эксперименты начинайте с quickstart.

```bash
python -m spot_contest validate --config examples/real-test-config.json \
  --data data/train/quickstart/events.jsonl
docker build -f Dockerfile.strategy -t spot-contest-strategy:real-test-20261109 .
python -m spot_contest evaluate --config examples/real-test-config.json \
  --data data/train/quickstart/events.jsonl --submission examples/baseline \
  --output runs/real-baseline-001 --image spot-contest-strategy:real-test-20261109
```

Новая фаза оценивает решения на отдельном закрытом часовом Validation.
Его история, отчёты и конфигурация сервера не входят в публичный архив.
Полный Train предназначен для исследования, часовой формат оценки — для
проверки SDK, очереди, изоляции и воспроизводимости. Эти тесты не устанавливают
достаточность данных и экономическую содержательность будущего призового конкурса.

## Фиксированные правила теста

Для локального запуска используйте актуальный `examples/real-test-config.json`
из репозитория вместе с событиями публичного quickstart.

| Правило | Значение |
|---|---|
| Комиссия | 10 bps за каждое исполнение, в USDT |
| Дополнительная задержка feed | 8 мс |
| Отправка заявки | 8 мс |
| Доставка отчёта | 7 мс |
| Виртуальное вычисление | 2 мс на callback |
| Доступная глубина | 5% уровня, с расходованием |
| Максимальный возраст стакана | 500 мс с учётом возраста источника |
| Капитал | По 25 000 USDT и 210,26 SOL на биржу |
| Опорная цена | 118,8950 USDT из начальных публичных Train-кадров |
| Стартовый номинал | 99 997,7254 USDT |

Сумма настроенных задержек от доступности события до доставки отчёта равна
25 мс — 8 мс feed + 2 мс вычисление + 8 мс заявка + 7 мс отчёт. До исполнения
заявки проходит 18 мс при свободном callback. Ожидание занятых callbacks
увеличивает фактическое время. История стаканов представлена срезами раз в
100 мс, а дополнительные задержки отсчитываются от доступности среза.

Все значения фиксируются в `config.json`, одинаковом для Train и закрытого
теста. Задержки и комиссии — правила симуляции, не измеренные характеристики
конкретных биржевых подключений. Остальные ограничения сохранены из API demo.
В конце исходный запас SOL восстанавливается отдельно на каждой бирже с
расходованием доступной глубины и taker-комиссией. Hold должен получать ноль.

В `examples/real-test-config.json` включён режим `require_paired_orders=true`.
Каждый вход содержит Buy и Sell одинакового объёма на разных биржах.
Ноги исполняются независимо, а остаток требуется захеджировать за
`max_unhedged_duration_ns=2000000000`, то есть за 2 секунды. Условия допуска
и завершения эпизода описаны в
[контракте стратегии](strategy-contract.md#обязательный-парный-вход).

Организатор обновляет evaluator и фиксированный конфиг серверного Judge,
затем публикует соответствующие правила и конфиг для локальных запусков участников.
Версии кода и правил фиксируются хешами в `run.json` каждого запуска.

## Стратегии для проверки

- `examples/hold`: контроль нулевого результата.
- `examples/baseline`: исходный арбитраж с фильтром расходов; может не торговать.
- `examples/cross_spread`: диагностический арбитраж положительного сырого спреда,
  без учёта комиссий в сигнале; демонстрирует издержки и риск исполнения одной ноги.
- `examples/broken`: ошибка должна приводить к Failed без числового score.

Оба торговых примера не реализуют полноценное аварийное хеджирование.
Нулевая или отрицательная доходность не считается технической ошибкой.
Результаты локального реального quickstart не должны сравниваться с synthetic demo.
