# Контракт стратегии и правила

## Сабмит и API

Поместите `strategy.py` с классом `Strategy` в корень ZIP, рядом с модулями и весами.
Рабочая директория — корень сабмита. Примеры находятся в `examples/baseline` и `examples/hold`.

Библиотеки в среде оценки устанавливает организатор. ML-модель можно использовать по желанию.

```python
class Strategy:
    def on_start(self, config, portfolio):
        return []

    def on_market_event(self, event, portfolio):
        return []

    def on_execution_report(self, report, portfolio):
        return []
```

Методы стратегии (callbacks) возвращают список заявок или `None`.
Обучение во время запуска использует общий лимит времени и только полученные данные.

- `config`: инструмент, активы, задержки, комиссии, спецификации и риск-лимиты.
- `portfolio`: наблюдаемые остатки, например `{"binance":{"base":"250","quote":"25000"},...}`.
- `book`: `exchange`, `symbol`, `is_snapshot`, `valid`, `update_id`, `stream_epoch`,
  `market_ts_ns`, `receive_ts_ns`, `bids`, `asks`. Уровни: `[["100","5.2"], ...]`.
  Из обновлений delta стратегия собирает стакан сама. Baseline использует полные снимки.
- `trade`: `price`, `qty`, `trade_id`, `is_buyer_maker`, временные метки.
- `report`: `id`, `exchange`, `status`, `reason`, `filled_qty`, `notional`, `fee`,
  `execution_ts_ns`, `now_ns` и наблюдаемый `portfolio`.

`now_ns` — время вызова метода стратегии. Оно может быть позже времени события.
Деньги и количества передаются строками, время — целыми наносекундами.

Отчёт содержит статус `Filled`, `PartiallyFilled`, `Canceled` или `Rejected`.
При частичном исполнении IOC оставшаяся часть заявки отменяется.

## Заявка

```json
{
  "id":"unique-id", "exchange":"binance", "category":"spot", "symbol":"SOLUSDT",
  "side":"Buy", "type":"Limit", "qty":"0.5", "price":"100.00",
  "time_in_force":"IOC", "reduce_only":false
}
```

`side` принимает `Buy` или `Sell`. ID должен быть уникальным в эпизоде, до 128 символов.
Заявка `Limit IOC` исполняется сразу в пределах указанной цены. Остаток отменяется.

Неизвестные поля, некорректные числа и нарушения шага цены, объёма или лимитов
приводят к отклонению заявки.

## Обязательный парный вход

Действует при `require_paired_orders=true`, как в `examples/real-test-config.json`.

- Возвращайте соседние пары `[buy, sell, ...]` с одинаковым объёмом на разных биржах.
  Обе заявки проходят проверки формата, балансов и лимитов.
- В полученных стратегией свежих стаканах должно хватать глубины в пределах
  limit-цен с учётом `depth_fraction` и округления до lot.
- Ноги исполняются независимо. Новые заявки разрешены после обработки всех отчётов.
- Остаток — суммарное изменение базового актива относительно стартовых запасов.
  При остатке разрешён только один IOC-хедж за вызов на любой бирже по исполнимой цене.
- Хедж должен сокращать остаток. Можно запросить больший объём для `min_notional`,
  но исполнится максимум величина остатка. После закрытия снова разрешены пары.
- Закройте остаток за `max_unhedged_duration_ns` от первого несбалансированного
  исполнения. В тесте это **2 секунды**, включая ожидание отчётов.
  Частичный хедж срок не продлевает.
- Незакрытый остаток к сроку или концу эпизода даёт `Failed` без score.

## Параметры demo

Параметры синтетического примера задаются в файле из `--config`.

| Поле | Пример |
|---|---|
| `venues.<биржа>.initial_base`, `initial_quote` | По 250 SOL + 25 000 USDT на площадку; `reference_price=100`, всего 100 000 USDT |
| `taker_fee_bps` | 10 bps = 0,1%, списание в USDT с каждого исполнения |
| `order_latency_ns`, `report_latency_ns` | Binance: 5/3 мс, Bybit: 8/4 мс |
| `extra_feed_latency_ns`, `compute_latency_ns` | Дополнительный feed: 0; вычисление: 1 мс |
| `trade_compute_latency_ns` | Отдельная стоимость trade-callback в наносекундах. `null` использует `compute_latency_ns`, допускается `0` |
| `depth_fraction`, `max_order_notional` | 5% глубины на уровень; до 1000 USDT на заявку |
| `turnover_window_ns`, `max_window_turnover` | До 5000 USDT на биржу за скользящую секунду |
| `max_net_exposure` | 2000 USDT при исполнении |
| `max_orders_per_callback`, `max_orders` | 8 на callback, 100 000 на эпизод |
| `max_book_age_ns` | 500 мс с учётом возраста источника |
| `callback_timeout_s`, `max_run_seconds` | 5 с на ответ, 1800 с на запуск стратегии — реальное время |

Лимит оборота за окно учитывает все принятые заявки по limit-цене, включая
неисполненные. При исполнении размер и оборот проверяются по фактической цене.
Часть IOC сверх лимита отменяется.

Net exposure — суммарное изменение базового актива относительно стартовых запасов,
умноженное на максимум `reference_price` и видимых ask-цен.
Лимит проверяется при исполнении, объём округляется вниз до lot.

Score учитывает восстановление запасов и комиссии. [Расчёт результата](architecture.md#итоговый-результат).
